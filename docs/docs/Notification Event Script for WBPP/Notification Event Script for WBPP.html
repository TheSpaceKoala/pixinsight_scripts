1 Introduction

[hide]

The Notification Event Script provides a way to receive real-time notifications during the execution of the Weighted Batch Preprocessing (WBPP) pipeline in PixInsight. This script supports multiple messaging platforms, including Telegram, Discord, iMessage, and Pushover, to send updates, error messages, and image notifications.

Support for Telegram text-only notifications was originally implemented by Marco Manenti. See his project at https://github.com/verbavolant/eventSendMessageToTelegram.

Support for Pushover notifications with images was contributed by Brian Weber, whose guide can be found at https://blog.briangweber.com/pushover-setup/.

2 Setup

[hide]

In order to use the Notification Event Script with WBPP (Weighted Batch Preprocessing), you first need to configure the notification system you want to use. This is done through the SendMessageToPhone script, which currently allows you to select Telegram, Discord, iMessage, or Pushover as the platform to receive notifications.

Follow the steps below to configure the notification system:

Step 1: Open the SendMessageToPhone script in PixInsight's Script Explorer.

Step 2: Select the messaging platform you want to use: Telegram, Discord, iMessage, or Pushover. Click its radio button.

Step 3a: If you selected Telegram, you will have to enter the Telegram Bot Token and Chat ID. To send notifications via Telegram, you'll need to Set up your Telegram Bot first. This feature was originally implemented by Marco Manenti, and a standalone version of his script can be found at https://github.com/verbavolant/eventSendMessageToTelegram.

Step 3b: If you selected iMessage, enter the Phone Number of the recipient in international format. For iMessage, enter the recipient of the person who will receive the notifications. This is likely your own Apple ID if you'd like to receive the notifications yourself, but technically you could insert any AppleID here. Ensure PixInsight has the rights to execute AppleScript: Run the script standalone once, at which point it will ask for the necessary permissions. Accept.

Step 3c: If you selected Pushover, enter your User Key and App Token. To use Pushover, you must create an account at https://pushover.net and register a new application. Copy the credentials and paste them into the appropriate fields. Pushover works across all operating systems and does not rely on a specific platform. Setup instructions and examples are available in Brian Weber’s guide at https://blog.briangweber.com/pushover-setup/.

Step 3d: If you selected Discord, create a webhook for the destination channel in Server Settings > Integrations > Webhooks, then paste its HTTPS Webhook URL into SendMessageToPhone. Creating a webhook requires the channel's Manage Webhooks permission. The URL allows posting to that channel and should be kept private.

Step 4: Save the configuration by clicking the Save Parameters button. Once you've filled out the necessary fields, click the Save Parameters button to save your settings. This will store the Bot Token, Chat ID, iMessage recipient, Pushover credentials, Discord webhook URL, and other options so that the script can send notifications during the WBPP process.

3 Usage

[hide]

Notifications typically include:

  • Current WBPP step
  • Operation status summary
  • Error message (in case of failure)

Automatic integrated-image delivery: On the WBPP done event for Integration or FastIntegration, the event script opens the integrated master light from WBPP's output directory. On the done event for Drizzle Integration, it opens the drizzle master instead. It then exports and sends a JPEG preview with a caption through the selected messaging platform. The preview is automatically stretched with an unlinked stretch; large images may be downsampled by the platform-specific sender. This happens automatically when these integration events finish, without a separate send command. The original master file is read; it is not the attachment uploaded. The opened master image window is left open in PixInsight.

Example messages:

WBPP started
ImageIntegration starting: processing 48/62 active frames
LocalNormalization failed, Cannot open reference image
WBPP terminated
ImageIntegration successfully executed

4 Setting up a Telegram Bot

[hide]

Setting Up a Telegram Bot

  • On your phone, open Telegram and search for the user BotFather.
  • Start a chat and type: newbot.
  • Follow the instructions to create a bot and receive an API token e.g. 63xxxxxx71:AAFoxxxxn0hwA-2TVSxxxNf4c.
  • Copy the bot token; you will need it for this script.

Finding Your Telegram Chat ID

  • Start a new chat with your new bot.
  • Visit the website https://api.telegram.org/bot63xxxxxx71:AAFoxxxxn0hwA-2TVSxxxNf4c/getUpdates - make sure to replace the bot token with the token you got from the BotFather.
  • It will show you a response similar to the following:

"ok": true,
"result": [
{
"update_id": 83xxxxx35,
"message": {
"message_id": 2643,
"from": {...},
"chat": {
"id": 123456789,
"first_name": "...",
"last_name": "...",
"username": "@username",
"type": "private"
},
"date": 1703062972,
"text": "/start"
} } ]}

  • The number you get in the chat section in the id field is your chat id.

5 Limitations

[hide]

  • The script uses the curl utility to interact with Telegram, Discord, and Pushover. Ensure your system has access to the internet and curl is available.
  • iMessage sending is only available on macOS. If you're running this script on Windows or Linux, use Telegram, Discord, or Pushover instead.
  • Pushover imposes a limit of 2.5MB on image attachments. If your image is too large, the script will downsample it. Only JPEG format is supported.
  • Notifications may be delayed if there is network congestion or if the bot/token/user credentials are incorrect.

6 Troubleshooting

[hide]

  • If no notifications are received, ensure the Telegram Bot Token and Chat ID, Discord Webhook URL, iMessage Recipient, or Pushover credentials are entered correctly.
  • Check if the curl utility is working properly on your system. You can test this by sending a test message manually using the command line.
  • If using Pushover, ensure that the image is smaller than 2.5MB, and that it is being saved as a valid JPEG.
  • If you receive a "No valid target image found" error, ensure there is an active image in PixInsight when running the script.

7 Network, External Programs, and File Storage

[hide]

This event script reads the configuration saved by SendMessageToPhone and uses the same messaging services, external programs, and temporary JPEG filenames described below. Text notifications describe WBPP operations, status, and errors; integrated-image previews are sent automatically as described in Usage.

Network connections and data sent

Only the selected messaging platform is used for notification delivery. Messages, captions, and JPEG previews are sent to the destination configured by the user.

  • Telegram: The script launches curl to make HTTPS POST requests to https://api.telegram.org/bot<BotToken>/sendMessage for text and https://api.telegram.org/bot<BotToken>/sendPhoto for images. Requests include the bot token, destination chat ID, message or caption, and the JPEG when sending an image.
  • Pushover: The script launches curl to make HTTPS POST requests to https://api.pushover.net/1/messages.json. Requests include the application token, user key, message, and an attached JPEG when sending an image.
  • Discord: The script launches curl to POST text or a JPEG with a message to the exact webhook URL saved in the configuration. Use the HTTPS webhook URL copied from Discord; the destination is determined by that URL.
  • iMessage (macOS only): The script launches osascript -e to execute AppleScript that controls Messages.app. Messages.app sends the text and, when applicable, the JPEG to the configured recipient using its signed-in iMessage service. Messages.app handles the network connection; the script does not use curl for iMessage. Messages must be configured, and macOS may request permission for PixInsight to control Messages.

Windows TLS retry

For Telegram, Pushover, and Discord, if curl exits with code 35 (a TLS handshake error) on Windows, the script retries the same request once with --ssl-revoke-best-effort. This enables best-effort certificate revocation checking with Windows Schannel; normal TLS certificate verification remains enabled. The option is not added on other operating systems or for other exit codes. If curl rejects the option with exit code 2, the script reports that curl 7.70.0 or newer is required.

JPEG files outside the PixInsight installation

Before sending an image, the script exports a JPEG copy into the system temporary directory reported by File.systemTempDirectory. Its location depends on the operating system and environment. The filename depends on the selected platform:

  • Telegram: TelegramProcessed.jpg
  • Pushover: PushoverProcessed.jpg
  • Discord: DiscordProcessed.jpg
  • iMessage: iMessageProcessed.jpg

These JPEG files are not deleted by the scripts after sending or after a failed send. A later export for the same platform uses the same filename and can replace the previous preview. Files may remain until the user or operating system removes them. Closing the temporary image window does not delete the exported JPEG. Remove the files manually only after the send has finished, particularly when Messages.app may still be reading an attachment.

Saved configuration

The Save Parameters button in SendMessageToPhone stores the selected platform, credentials, recipient, message, and image options in PixInsight's persistent per-user settings store, under keys beginning with SendMessageToPhone/. This is the settings location managed by PixInsight for the current user, outside the installation directory. Reset Parameters removes those saved script settings. If a process icon containing these parameters is saved to a file, that file is stored at the location chosen by the user and can also contain the credentials.
